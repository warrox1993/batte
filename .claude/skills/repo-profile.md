## Integration style
- **Merge mode:** squash — décision de JB du 28/09/2026 : fusion squash seule, comme le kit
  (commit de fusion et rebase désactivés dans `.github/repo-setup.yml`). Le titre de la PR devient
  le sujet du commit sur la branche par défaut, suivi de `(#<PR>)` ; `merge-pr` et
  `guarded-pr-merge.sh` fusionnent ainsi par défaut. Historique antérieur : commits de fusion.
- **PR title convention:** pas de contrôle de titre en CI. Commits conventionnels en français
  (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `ci:`, `chore:`, `perf:` — `CLAUDE.md` §4) ;
  titre de PR au même format, terminé par `(#<issue>)` quand une issue existe. Sujet du commit de
  fusion observé : `Fusion de <branche> : <résumé> (#<PR>)`.
- **Branch naming:** branches en français décrivant le travail (`finition-cv`,
  `relecture-readme`, `securite-dependances`) ; pour le kit : `<type>/<issue>-<slug>`.

## Conflict hot-spots (merge-with-main resolutions)
| File | Why it collides | Resolution |
|------|-----------------|------------|
| `package-lock.json` | churn des dépendances | **regenerate** (`npm install`), jamais à la main |
| `packages/db/drizzle/` (migrations + `meta/`) | générés par `npm run db:generate` | **regenerate** ; deux migrations concurrentes = conflit sémantique, renuméroter en régénérant |
| `docs/05-DECISIONS.md` | journal où chaque lot ajoute une entrée | **union**, numéros D-xxx renumérotés si doublon |
| `README.md`, `docs/` | chaque lot documente ce qu'il livre | **union** |
| fichiers de tests | chaque branche ajoute des tests | **union** |
- **Rule of thumb:** union additive files, regenerate derived files, take-the-higher for the version;
  same-logic-both-sides is a real semantic conflict — understand both intents or stop.

## Architecture grain / invariants (shape implementation plans to these)
- Toute logique métier chiffrée vit dans `packages/core`, en fonctions pures testées — jamais dans
  un composant React ni un handler Fastify.
- Un LLM ne calcule jamais : sortie Claude → schéma Zod strict, `source = 'ia'`, validation humaine.
- Argent en centimes (entiers), masses en grammes, volumes en millilitres ; aucune conversion implicite.
- Le stock ne change que par un mouvement ; rien ne s'efface (annulation, pas de `DELETE`).
- Traçabilité par lot, FEFO ; fuseau `Europe/Brussels` ; aucune donnée personnelle client en V1.
- Ordre des couches : `packages/db` (schéma) → `packages/core` → `apps/api` → `apps/web` → tests.
- Toute décision d'architecture nouvelle est consignée dans `docs/05-DECISIONS.md`.
